## วิธีรัน

```bash
npm install
npm start
```

แล้วเปิดเบราว์เซอร์ที่ **http://localhost:3000**

> เปิดผ่าน `http://` เท่านั้น (อย่าดับเบิลคลิกเปิดไฟล์ `index.html` ตรง ๆ
> เพราะ `fetch` กับ ES module จะถูกบล็อกโดย browser)
> `server.js` เป็นแค่ static server — ใช้ `python3 -m http.server -d public 3000` แทนก็ได้

ไม่มีโค้ดฝั่งเซิร์ฟเวอร์: หน้าเว็บดึง Google Sheets เองจากในเบราว์เซอร์ (`public/js/sheets.js`)
เพราะ gviz ของ Google เปิด CORS ให้ทุกโดเมน — บนเครื่องตัวเองจึงได้ข้อมูลจริงเหมือนบนเว็บทุกประการ
ต่อชีตไม่ได้เมื่อไร หน้าเว็บตกไปใช้ `data/mock.json` เอง (มีแจ้งใน console ว่ากำลังโชว์ข้อมูลตัวอย่าง)

## Deploy ขึ้น GitHub Pages

เว็บอยู่ที่ **https://patumwansport.github.io/satit-sports-dashboard/**

**push ขึ้น `main` แล้วจบ** — workflow `.github/workflows/pages.yml` จะ build และเผยแพร่ให้เอง
ใช้เวลาราว 1 นาที ดูความคืบหน้าที่แท็บ **Actions** ของ repo (กด "Run workflow" ตรงนั้นเพื่อ deploy ซ้ำได้)

```bash
git add -A && git commit -m "..."
git push origin main
```

ตั้งค่าไว้แล้วที่ repo → Settings → Pages → Source = **GitHub Actions** — ถ้าใครไปเปลี่ยนเป็น
"Deploy from a branch" workflow จะรันจบแต่ Pages ไม่หยิบผลลัพธ์ไปใช้ เว็บจะค้างเวอร์ชันเก่า

> การ push ไฟล์ใน `.github/workflows/` ต้องใช้โทเคนที่มีสิทธิ์ `workflow`
> ถ้าเจอ "refusing to allow an OAuth App to create or update workflow" ให้รัน
> `gh auth refresh -h github.com -s workflow` (ล็อกอินในเบราว์เซอร์ด้วยบัญชีเดียวกับ `gh`)

สิ่งที่ต้องรู้เพราะ Pages เสิร์ฟได้แค่ไฟล์นิ่ง ๆ:

1. **ไม่มีเซิร์ฟเวอร์** — การดึง Google Sheets ทั้งหมดทำในเบราว์เซอร์ (`public/js/sheets.js`)
   และรูปจาก Google Drive ก็โหลดตรงจาก Drive (ผ่าน `drive.google.com/thumbnail?id=…`)
   ชีตกับไฟล์รูปจึง **ต้องแชร์แบบ "ทุกคนที่มีลิงก์ดูได้"** ไม่งั้นเบราว์เซอร์ของคนดูจะเข้าไม่ได้
2. **ทุกเบราว์เซอร์ยิงชีตเอง** รอบละ 5 คำขอ **ครั้งเดียวตอนเปิดหน้า** (ไม่มีแคชรวมเหมือนตอนมีเซิร์ฟเวอร์)
   ไม่มีการเช็กข้อมูลซ้ำเป็นระยะ หน้าไม่เปลี่ยนเองระหว่างอ่าน — ผลใหม่เห็นเมื่อผู้ใช้รีเฟรช/เปิดหน้าใหม่
   (ดู `onFreshData` ใน `public/js/common.js`)
3. **เว็บอยู่ใต้ path ย่อย** (`/satit-sports-dashboard/`) — ลิงก์และ `fetch` ในโค้ดจึงเป็น
   path แบบสัมพัทธ์ทั้งหมด (`css/app.css`, `data/mock.json`) ห้ามขึ้นต้นด้วย `/`
4. **repo ต้องเป็น public** — Pages บน repo private ใช้ได้เฉพาะแพลนเสียเงิน (ใน repo ไม่มีรหัสลับ
   Sheet ID ก็เปิดสาธารณะอยู่แล้ว)

คำสั่ง build คือ `npm run build` = คอมไพล์ Tailwind + ก๊อป `fonts/` กับ
`data/mock.json` เข้า `public/` (ทั้งสองอย่างอยู่นอก `public/` จึงไม่ถูก deploy เอง)

## CMS หลังบ้าน (Supabase) — ตอนนี้ปิดใช้งานอยู่

> **สถานะปัจจุบัน: เว็บใช้ Google Sheets เป็นแหล่งข้อมูล** ไม่ได้ใช้ Supabase
>
> ระบบ CMS สร้างเสร็จและทดสอบผ่านแล้ว แต่ตัดสินใจกลับไปใช้ชีตเหมือนเดิม
> โค้ดทั้งหมดยังอยู่ในสภาพพร้อมใช้ ปิดไว้ด้วยการเว้น `public/js/config.js` ให้ว่าง
> ตราบใดที่สองค่านั้นว่าง `admin.html` จะขึ้นหน้า "ยังไม่ได้เชื่อมต่อฐานข้อมูล"
> และหน้าเว็บสาธารณะจะดึงจากชีตตามปกติ — ไม่มีอะไรวิ่งไป Supabase เลย
>
> โปรเจกต์ที่สร้างไว้ยังอยู่ (ref `nrnblsmwfixxijawaevl`, org "Satit Patumwan")
> พร้อมตารางและข้อมูลที่ย้ายเข้าไปแล้ว ณ 23 ก.ย. 2569
>
> **เปิดใช้อีกครั้ง** = กรอก `SUPABASE_URL` กับ `SUPABASE_KEY` กลับเข้า `config.js` เท่านั้น
> (ถ้าข้อมูลในฐานล้าสมัยแล้ว ให้รัน `npm run import:sheets` ดึงจากชีตทับอีกรอบ)

หน้า `admin.html` ให้ทีมงานแก้ผลการแข่งขัน เหรียญ ตารางแข่ง และภาพได้จากเว็บโดยตรง
ไม่ต้องเปิด Google Sheets — ข้อมูลเก็บใน Supabase และหน้าเว็บสาธารณะอ่านจากที่เดียวกัน

**ลำดับแหล่งข้อมูลของหน้าเว็บ** (`public/js/common.js`)

1. **Supabase** — ใช้เมื่อกรอก `public/js/config.js` แล้วเท่านั้น (ตอนนี้เว้นว่าง = ข้าม)
2. **Google Sheets** — แหล่งที่ใช้จริงอยู่ตอนนี้ และเป็นตัวสำรองอัตโนมัติถ้าวันหน้าเปิด Supabase
3. **`data/mock.json`** — กันหน้าว่างเมื่อไม่เหลือทางไหนเลย

ข้อ 2 ไม่ได้มีไว้แค่ช่วงย้ายระบบ: วันแข่งจริงถ้า Supabase มีปัญหา เว็บยังขึ้นผลจากชีตได้
ตราบใดที่ยังไม่ปิดแชร์ชีตทิ้ง

### ติดตั้งครั้งแรก (ถ้าวันหน้าจะเปิดใช้ หรือสร้างโปรเจกต์ใหม่)

```bash
# 1) สร้าง organization + โปรเจกต์ (ครั้งแรกต้องทำในหน้าเว็บ CLI สร้าง org เองไม่ได้)
#    https://supabase.com/dashboard  →  New project  (เลือก region Southeast Asia)

# 2) ผูกโฟลเดอร์นี้เข้ากับโปรเจกต์ แล้วส่งโครงตารางขึ้นไป
supabase link --project-ref <project-ref>
npm run db:push

# 3) กรอก URL และ publishable key ลงใน public/js/config.js
#    หาได้ที่ Dashboard → Project Settings → API

# 4) (ถ้าต้องการ) ย้ายข้อมูลเดิมจากชีตเข้าฐานข้อมูล — ลองดูผลก่อนได้
npm run import:sheets -- --dry-run
SUPABASE_URL=https://xxxx.supabase.co SUPABASE_SERVICE_KEY=<service_role key> npm run import:sheets
```

### เพิ่มผู้ดูแล

สมัครผู้ใช้ไม่ได้จากหน้าเว็บโดยตั้งใจ — ต้องเพิ่มให้ทีละคน สองขั้นตอน

1. Dashboard → **Authentication → Users → Add user** ใส่อีเมลกับรหัสผ่าน
2. Dashboard → **SQL Editor** รันคำสั่งนี้เพื่อให้สิทธิ์แก้ข้อมูล

```sql
insert into public.app_admins (user_id, email, display_name)
select id, email, 'ชื่อที่จะให้แสดง' from auth.users where email = 'someone@example.com';
```

ล็อกอินได้แต่ยังไม่ได้อยู่ใน `app_admins` = เข้าหน้า CMS ไม่ได้ และต่อให้เรียก API เอง
ฐานข้อมูลก็ปฏิเสธ เพราะ RLS ตรวจที่ตารางนี้ทุกครั้ง

**ถอนสิทธิ์** ลบแถวออกจาก `app_admins` (บัญชียังอยู่แต่แก้อะไรไม่ได้แล้ว)

### ความปลอดภัย

เว็บอยู่บน GitHub Pages ซึ่งไม่มีเซิร์ฟเวอร์ของเรา เบราว์เซอร์จึงคุยกับ Supabase ตรง ๆ
ด่านกันจริงมีชั้นเดียวคือ **RLS ในฐานข้อมูล** ไม่ใช่การซ่อนหน้า `admin.html` หรือซ่อนคีย์

| คีย์ | ใส่ไว้ที่ไหนได้ | ทำอะไรได้ |
|---|---|---|
| publishable (anon) | `public/js/config.js` · commit ขึ้น repo ได้ | อ่านได้ทุกตาราง · เขียนได้เฉพาะเมื่อล็อกอินเป็นผู้ดูแล |
| `service_role` | environment variable ตอนรันสคริปต์เท่านั้น | **ข้าม RLS ทั้งหมด** — หลุดเมื่อไรคือเสียฐานข้อมูล |

ห้ามเอา `service_role` ใส่ใน `public/` หรือ commit ลง repo เด็ดขาด

### แก้โครงตาราง

แก้ที่ `supabase/migrations/` แล้ว `npm run db:push` เสมอ อย่าแก้ในหน้า Table Editor ตรง ๆ
ไม่งั้นฐานข้อมูลจริงกับไฟล์ใน repo จะไม่ตรงกัน แล้ววันที่ต้องสร้างโปรเจกต์ใหม่จะสร้างกลับมาไม่เหมือนเดิม

## CMS สำรอง (โฟลเดอร์ `admin/`)

ระบบหลังบ้านชุดที่สอง เปิดที่ **`/admin/`** ของเว็บ (บนเครื่อง: http://localhost:3000/admin/)
ใช้ฐานข้อมูล Supabase ชุดเดียวกับ `admin.html` แต่เปิด/ปิดแยกกันได้ และทำได้มากกว่า:

| เมนู | ทำอะไร |
|---|---|
| ผู้เข้าชมเว็บไซต์ | ผู้เข้าชมวันนี้ · กำลังดูอยู่ (5 นาทีล่าสุด) · กราฟรายวัน 7/14/30 วัน · หน้าที่เปิดมากที่สุด |
| ผลการแข่งขัน … ตั้งค่าเว็บ | แก้ข้อมูลทุกหมวดที่หน้าเว็บแสดง (มีช่องค้นหาในทุกตาราง) |
| แบนเนอร์ประกาศ | แถบประกาศบนสุดของหน้าเว็บ — แบบข้อความ 4 สี หรือแบบรูป · ตั้งเวลาเริ่ม/หมด · ทุกหน้าหรือหน้าหลักอย่างเดียว · ผู้ชมกดปิดได้ |
| สำรองและกู้คืนข้อมูล | ดาวน์โหลดทุกตารางเป็น .json · กู้คืนจากไฟล์ · **ดึงข้อมูลล่าสุดจาก Google Sheets เข้าฐานข้อมูล** |

**ทำไมถึงเรียกว่า "สำรอง"** — หน้าเว็บยังอ่านผลการแข่งขันจาก Google Sheets เหมือนเดิม
กรอก `public/admin/config.js` แล้วสิ่งที่เปิดคือ CMS + การนับผู้เข้าชม + แบนเนอร์เท่านั้น
ไม่มีอะไรสลับแหล่งข้อมูล (ตัวสลับคือ `public/js/config.js` คนละไฟล์กัน)
ระหว่างแข่งให้กด "ดึงจาก Google Sheets" เป็นระยะ ฐานข้อมูลจะมีข้อมูลตรงกับหน้าเว็บเสมอ
วันไหนชีตใช้ไม่ได้ ก็กรอก `public/js/config.js` ด้วยค่าเดียวกัน หน้าเว็บจะอ่านจากฐานข้อมูลนี้แทนทันที

### เปิดใช้งาน

```bash
# 1) ส่งตารางใหม่ขึ้นฐานข้อมูล (page_visits, banners + ฟังก์ชัน track_visit / visit_stats)
supabase link --project-ref <project-ref>
npm run db:push

# 2) กรอก SUPABASE_URL กับ SUPABASE_KEY (publishable key) ใน public/admin/config.js
# 3) npm run build แล้ว commit + push
```

บัญชีผู้ดูแลใช้ชุดเดียวกับหัวข้อ "เพิ่มผู้ดูแล" ข้างบน (ต้องอยู่ในตาราง `app_admins`)

**ลืมรหัสผ่าน** — ปุ่มในหน้าเข้าสู่ระบบส่งลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล ลิงก์จะพากลับมาที่ `/admin/`
ซึ่ง Supabase ยอมพาไปเฉพาะที่อยู่ที่อนุญาตไว้ — ตั้งครั้งเดียวที่ Dashboard → **Authentication → URL Configuration
→ Redirect URLs** เพิ่ม `https://patumwansport.github.io/satit-sports-dashboard/admin/` และ `http://localhost:3000/admin/`
(ไม่ตั้ง = ลิงก์ในอีเมลพาไปหน้า Site URL แทน ตั้งรหัสใหม่ไม่ได้)
อีเมลของ Supabase แพลนฟรีส่งได้ไม่กี่ฉบับต่อชั่วโมง ถ้าทีมใหญ่ขึ้นให้ต่อ SMTP ของตัวเองที่ Authentication → Emails

**แจ้งคุกกี้** — หน้าเว็บสาธารณะขึ้นกล่อง "คุกกี้บนเว็บไซต์นี้" มุมขวาล่างครั้งแรกที่เข้าชม
(แจ้งเรื่องรหัสผู้เข้าชมที่ใช้นับยอด) กด "ยอมรับ" แล้วไม่ขึ้นอีกในเบราว์เซอร์นั้น

### การนับผู้เข้าชมทำงานอย่างไร

ทุกหน้าโหลด `admin/site.js` ซึ่งส่ง "เปิดหน้า X" ไปที่ฟังก์ชัน `track_visit` หนึ่งครั้ง
- **ผู้เข้าชม** = รหัสสุ่มที่เบราว์เซอร์เก็บไว้ใน localStorage ไม่เก็บ IP ไม่ผูกกับตัวบุคคล
  (คนเดียวเปิดหลายเครื่อง/ล้างข้อมูลเบราว์เซอร์ จะถูกนับเป็นหลายคน)
- คนเดิมเปิดหน้าเดิมซ้ำภายใน 30 นาทีไม่นับเพิ่ม · ตัดรอบวันตามเวลาไทย
- เก็บแหล่งที่มาเป็นชื่อโดเมนเท่านั้น (เช่น `facebook.com`) ไม่เก็บ URL เต็ม
- คนทั่วไปเขียนได้ผ่านฟังก์ชันนั้นทางเดียว อ่านสถิติได้เฉพาะผู้ดูแล
- ไฟล์นี้แยกจากสคริปต์หลักของหน้า Supabase ล่มหรือช้าแค่ไหน แดชบอร์ดก็ไม่พังตาม

> ข้อจำกัด: ไม่มีเซิร์ฟเวอร์ของเราคั่น ใครตั้งใจยิง API ปลอมยอดก็ทำได้ (ฟังก์ชันตัดความยาวข้อความ
> และกันการนับซ้ำให้แล้ว แต่ไม่ได้กันบอท) — ใช้ดูแนวโน้ม ไม่ใช่ตัวเลขทางการ

## ฟังก์ชันหลัก

- **หน้าแรก** — ภาพประจำวัน (สไลด์) + การ์ดสรุปของโรงเรียนเรา, การ์ดแมตช์ที่กำลังแข่ง,
  อันดับเหรียญ 8 อันดับแรก และประกาศผลล่าสุด
- **ผลการแข่งขันสด** — การ์ดสถานะ กำลังแข่ง / จบแล้ว พร้อมสกอร์
- **แท็บเลือกวัน** — สลับตารางแข่งขันและตัวเลขสดตามแต่ละวัน (วันนี้ / วันถัดไป)
- **ตารางแข่งขันรายวัน** — ไทม์ไลน์เรียงตามเวลา พร้อมไอคอนกีฬาและสถานที่
- **ตารางการแข่งขัน** (`schedule.html`) — ผังกำหนดการทั้งรายการ แยกพาเนลต่อวัน
  ไม่แบ่งหน้าและไม่ตัดข้อมูล ใช้เป็นผังอ้างอิง อ่านจากแท็บ **"ตารางการแข่งขัน"**
  ในชีต (`GID_SCHEDULE_PLAN` ใน `public/js/sheets.js`) คอลัมน์: วันที่ / กีฬา / ประเภท / เวลา /
  ทีม A / VS / ทีม B — แท็บนี้ไม่มีช่องผลกับสถานะ หน้านี้จึงไม่มีคอลัมน์ผล/สถานะ
  (ผลอยู่ที่หน้า "ตารางแข่งขัน" ซึ่งอ่านจากแท็บ "ผลการแข่งขันประจำวัน")
- **ตารางเหรียญ** — จัดอันดับอัตโนมัติ ไฮไลต์โรงเรียนเรา และลูกศรบอกทิศทางอันดับ
- **ชนิดกีฬาที่ส่งแข่ง** — การ์ดมาสคอตรายกีฬา แตะ/คลิกการ์ดเพื่อเปิดป๊อปอัป
  ที่บอกสถานะ จำนวนเหรียญ และรายการแข่งขันของกีฬานั้น (ปิดด้วย Esc / กากบาท / แตะนอกกล่อง)
- **สลับโหมดสว่าง/มืด** — จำค่าไว้ใน localStorage

## ภาพประจำวันบนหน้าแรก

แถบภาพบนสุดของหน้าแรกแสดง **เฉพาะภาพของวันที่กำลังแข่งอยู่ ในกีฬาของวันนั้น**
วันที่ถูกเลือกอัตโนมัติตามลำดับ: วันที่มีแมตช์สด → วันล่าสุดที่ประกาศผลแล้ว → วันแรกของรายการ
ถ้าวันนั้นยังไม่มีภาพ หน้าเว็บจะขึ้นข้อความบอกตรง ๆ ไม่ดึงภาพของวันอื่นมาแสดงแทน

ข้อมูลภาพอยู่ในฟิลด์ `photos` ของ API (ดูตัวอย่างใน `data/mock.json`):

```json
{ "id": "d1-football", "dayId": 1, "sportId": "football", "time": "10:30",
  "caption": "ฟุตบอลชาย รอบคัดเลือก สาย A", "venue": "สนามฟุตบอล",
  "credit": "ฝ่ายประชาสัมพันธ์", "src": "assets/photos/day1-football.svg" }
```

**วิธีต่อกับชีตจริง** — สร้างแท็บใหม่ในชีตเดิม คอลัมน์เรียงตามนี้

| วันที่ | กีฬา | เวลา | คำบรรยาย | สถานที่ | ลิงก์รูป | เครดิต |
|---|---|---|---|---|---|---|

แล้วใส่ชื่อแท็บนั้นที่ค่า `SHEET_PHOTOS` ใน `public/js/sheets.js` (ค่าว่าง = ยังไม่เปิดใช้)
ลิงก์แชร์จาก Google Drive ใส่ได้เลย หน้าเว็บแปลงเป็นลิงก์รูปตรงให้เอง
(ไฟล์รูปต้องแชร์แบบ "ทุกคนที่มีลิงก์ดูได้" เพราะเบราว์เซอร์ของคนดูเป็นคนโหลดรูปเอง)
วันที่ในแท็บนี้ต้องตรงกับวันในตารางแข่งขัน ไม่งั้นภาพนั้นจะถูกข้าม
ถ้าอ่านแท็บนี้ไม่สำเร็จ ส่วนอื่นของแดชบอร์ดยังทำงานตามปกติ

> ไฟล์ใน `public/assets/photos/` เป็นภาพตัวอย่างสำหรับข้อมูล mock เท่านั้น
> เมื่อมีภาพถ่ายจริงแล้วลบทิ้งได้

## เปลี่ยนไอคอนเป็นรูปภาพจริง (ในอนาคต)

ตอนนี้ไอคอนแต่ละกีฬาคือไฟล์ `public/assets/icons/<id>.svg` แสดงผ่าน CSS mask
(รับสีจากธีมอัตโนมัติ) — เมื่อมีรูปจริง มี 2 ทางเลือก:

1. แทนไฟล์ `.svg` ด้วยภาพเวกเตอร์ใหม่ (ใช้ mask ต่อได้ทันที) หรือ
2. ใช้ภาพถ่าย (`.png/.jpg/.webp`) → ใน `styles.css` เปลี่ยนคลาส `.sport-ic`
   จาก `mask` เป็น `background-image` และวางไฟล์ในโฟลเดอร์เดิม

รหัสกีฬา (`id`) ที่ใช้ตั้งชื่อไฟล์: `athletics, golf, tennis, tabletennis,
basketball, basketball3x3, badminton, petanque, football, dancesport,
swimming, boardgame, handball, volleyball`

## การเชื่อมต่อ Google Sheets

ทั้งหมดอยู่ใน `public/js/sheets.js` — อ่านชีตผ่าน Google Visualization API (gviz)
ซึ่งใช้ได้กับชีตที่แชร์แบบ "ทุกคนที่มีลิงก์ดูได้" โดยไม่ต้องมี API key และเปิด CORS ให้ทุกโดเมน

ค่าที่ต้องรู้เมื่อชีตเปลี่ยน: `SHEET_ID`, ชื่อ/gid ของแต่ละแท็บ (`SHEET_MEDAL_TABLE`,
`GID_SPORT_MEDALS`, `GID_SCHEDULE`, `GID_SCHEDULE_PLAN`, `SHEET_PHOTOS`) และ `SELF_SCHOOL_NAME`
(ชื่อโรงเรียนเราสะกดตรงตามชีต ใช้จับแถว "ของเรา")

ฟังก์ชัน `loadFromSheets()` คืน object ที่มี schema เดียวกับ `data/mock.json`
หน้าเว็บทุกหน้ารับ object นี้ผ่าน `loadData()` ใน `common.js` — ถ้าวันหลังเปลี่ยนแหล่งข้อมูล
(เช่น Apps Script Web App) แก้แค่ไฟล์นี้ให้คืน schema เดิม frontend ไม่ต้องแตะ
